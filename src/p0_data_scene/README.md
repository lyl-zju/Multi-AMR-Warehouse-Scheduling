# P0 二维仓库场景建模

P0 是整个项目的空间基准层，负责把 `data/raw/` 中的节点、区域、障碍物、AMR 初始位置和任务点绘制成统一的二维仓库平面图。后续 P1 的路径规划、P2 的任务链解释、P3/P4 的轨迹冲突检测和 P5 的热点分析，都以这张二维场景为共同参照。

## 本部分在做什么

P0 读取原始 CSV 数据，完成三类可视化表达：

| 内容 | 说明 |
| --- | --- |
| 功能区域 | 入库区、出库区、分拣区、充电区等仓库区域 |
| 障碍物 | 货架块、墙体、动态风险或封锁区域 |
| 关键点 | AMR 初始位置、取货点、送货点、充电点和任务相关节点 |

P0 不求解优化问题，也不生成路径；它的作用是把后续所有模块使用的二维坐标系统可视化出来，便于检查数据是否合理、障碍物是否覆盖正确、任务点与 AMR 初始点是否落在预期位置。

## 输入

```text
data/raw/nodes.csv
data/raw/amrs.csv
data/raw/tasks.csv
data/raw/floor_zones.csv
data/raw/floor_obstacles.csv
```

字段含义：

| 文件 | 作用 |
| --- | --- |
| `nodes.csv` | AMR 初始点、取货点、分拣点、出库点、充电点等二维坐标 |
| `amrs.csv` | AMR 初始节点、电量、速度系数 |
| `tasks.csv` | 任务取货点、送货点、服务时间、时间窗和优先级 |
| `floor_zones.csv` | 仓库功能区域矩形 |
| `floor_obstacles.csv` | 墙体、货架块、动态封锁或风险区域 |

## 采用的方法

P0 采用基于二维矩形和散点的场景渲染方法：

1. 用 `Rectangle` 绘制仓库边界、功能区域和障碍物。
2. 用不同颜色和 marker 区分入库口、出库口、货架点、分拣点、充电点和普通路口。
3. 根据 `amrs.csv` 在初始节点附近绘制 AMR 初始位置。
4. 根据 `tasks.csv` 在取货点和送货点附近叠加任务标记。
5. 输出一张稳定的仓库平面图，用于报告和后续结果解释。

这里没有额外优化算法，重点是统一坐标、图层和图例。报告中的 P0 图正是后续路径、任务链和动态轨迹图的底图语义来源。

## 运行

在项目根目录运行：

```powershell
python .\src\p0_data_scene\plot_floor_plan.py
```

## 输出

```text
outputs/p0/warehouse_floor_plan.png
```

该图展示仓库功能区、货架和墙体障碍、动态封锁区、任务取送货点以及 AMR 初始位姿。报告中也使用该图说明仓库二维建模结果。

## 达到的效果

P0 将抽象 CSV 数据转化为直观的二维仓库场景，完成了以下检查和支撑作用：

- 验证节点、区域和障碍物都处于同一坐标系。
- 明确 P1 路径规划需要避让的货架和墙体区域。
- 为 P2 的任务链空间分布图、P3 的轨迹冲突图、P4 的动态重排图提供底图解释。
- 为 P5 的轨迹占用热图和瓶颈区域解释提供空间语义。

## 代码简要解读

核心文件为 `plot_floor_plan.py`：

| 函数/变量 | 作用 |
| --- | --- |
| `DATA_DIR` / `OUTPUT_DIR` | 定位原始数据和 P0 输出目录 |
| `ZONE_STYLE`、`OBSTACLE_STYLE`、`POINT_STYLE` | 定义区域、障碍物和关键节点的颜色与样式 |
| `load_data()` | 读取 `nodes.csv`、`amrs.csv`、`tasks.csv`、`floor_zones.csv` 和 `floor_obstacles.csv` |
| `draw_rectangles()` | 按矩形字段绘制功能区和障碍物，并添加标签 |
| `plot_floor_plan()` | 组合底图、区域、障碍物、节点、AMR 和任务点，保存 PNG |
| `main()` | 串联读取数据、绘图和保存结果 |

代码只读 `data/raw/`，只写 `outputs/p0/warehouse_floor_plan.png`，不会修改后续模块的数据。

## 与后续模块的关系

P0 输出的是空间解释基准。P1 根据同一批节点和障碍物生成路径；P2 将任务链投影到仓库平面解释调度结果；P3/P4 将 AMR footprint 轨迹叠加到同一空间中检查冲突；P5 进一步把轨迹点投影到网格单元，识别高占用区域和瓶颈通道。
