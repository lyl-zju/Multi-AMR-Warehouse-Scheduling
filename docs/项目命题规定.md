# 项目命题规定

## 1. 题目名称

动态仓储环境下多 AMR 任务分配与路径协同调度优化。

## 2. 问题背景

仓库被抽象为带障碍物的二维平面，入库区、货架、分拣台、出库区、充电点等关键节点分布其上。多台 AMR 从各自初始位置出发，需要完成一批取送货任务。每个任务包含取货点、送货点、服务时间、时间窗和优先级。系统需要在固定仓库平面布局、固定 AMR 初始状态和固定任务集合下，生成可执行调度方案。

本题研究的是运筹学调度问题，不研究真实机器人定位、控制、避障和轨迹跟踪。

核心决策包括：

```text
1. 哪台 AMR 执行哪个任务；
2. 每台 AMR 按什么顺序执行任务；
3. 每段移动选择哪条候选路径；
4. 每个任务何时开始、何时完成；
5. 如何避免 AMR 之间的二维轨迹冲突；
6. 动态事件发生后如何重排；
7. 如何满足电量阈值约束，并在进阶层中处理充电调度。
```

## 3. 固定输入

### 3.1 仓库节点

节点由 `data/raw/nodes.csv` 给定。节点位置、节点类型和所属区域固定，不由算法改变。

节点类型包括：

```text
inbound    入库点
shelf      货架点
sorting    分拣台
outbound   出库点
charger    充电点
junction   路口
```

当前算例中，`CHG1` 和 `CHG2` 为充电点。

### 3.2 仓库平面图

仓库平面由 `data/raw/floor_zones.csv`（二维功能区域）和 `data/raw/floor_obstacles.csv`（墙体、货架块、动态风险/封锁区域）给定。区域与障碍物布局固定，不由算法改变。

AMR 在平面内绕开障碍物移动，路径由 P1 的二维路径规划器生成：

```text
basic_astar   二维栅格 8 邻域 A*，仅按几何距离搜索
vg            可见图最短路
avg           在可见图上加入转角代价
davg          在 AVG 基础上加入动态区域代价
```

动态风险区域在路径成本中以 `dynamic_cost` 体现，临时封锁区域由动态事件 `area_block` 给出。

### 3.3 AMR

AMR 由 `data/raw/amrs.csv` 给定。

字段含义固定如下：

```text
amr_id       AMR 编号
init_node    初始位置
battery      初始电量
speed        相对速度系数
```

`speed = 1.0` 表示按路径基准通行时间行驶；`speed > 1.0` 表示更快；`speed < 1.0` 表示更慢。

### 3.4 任务

静态任务由 `data/raw/tasks.csv` 给定。

字段含义固定如下：

```text
task_id          任务编号
pickup           取货点
delivery         送货点
service_time     取货服务时间
earliest_start   最早开始时间
latest_finish    期望最晚完成时间
priority         优先级，数值越大越重要
```

所有静态任务必须完成。

## 4. 任务执行规则

每个任务必须由同一台 AMR 从取货点运到送货点完成。任何层次均不允许任务中途接力。

若 AMR 当前位于 `current_node`，执行任务 `j` 的过程固定为：

```text
current_node -> pickup_j        空驶
到达 pickup_j 后等待到 earliest_start_j
在 pickup_j 服务 service_time_j
pickup_j -> delivery_j          载货
任务 j 完成，AMR 停在 delivery_j
```

若同一台 AMR 连续执行任务 `i -> j`，则必须存在：

```text
delivery_i -> pickup_j
```

的可行路径。否则该任务顺序不可行。

## 5. 时间规则

### 5.1 基准路径时间

P1 生成的 `path_cost.csv` 中的 `travel_time` 是路径基准通行时间，表示速度系数为 1.0、空驶状态下的时间。

### 5.2 AMR 实际通行时间

AMR `k` 走路径 `p` 的空驶时间为：

```text
empty_time[k,p] = base_travel_time[p] / speed[k]
```

载货速度固定比空驶慢，载货时间为：

```text
loaded_time[k,p] = base_travel_time[p] / (speed[k] * loaded_speed_factor)
```

固定取值：

```text
loaded_speed_factor = 0.90
```

即载货时有效速度为空驶速度的 90%。

### 5.3 时间窗

最早开始时间是硬约束：

```text
start_time[j] >= earliest_start[j]
```

期望最晚完成时间是软约束。若任务晚于 `latest_finish` 完成，则产生延期：

```text
delay[j] = max(0, finish_time[j] - latest_finish[j])
late[j] = 1 if delay[j] > 0 else 0
```

## 6. 电量与充电规则

电量消耗和电量阈值从基础层开始启用。充电规则只在进阶层启用，基础层不插入充电任务。

### 6.1 电量单位

`battery` 是抽象电量单位，不解释为真实百分比或千瓦时。

所有 AMR 的最大电量固定为：

```text
max_battery = 100
```

安全电量阈值固定为：

```text
battery_safety_threshold = 10
```

基础层和进阶层中，任意时刻 AMR 剩余电量不得低于该阈值。若 AMR 剩余电量低于该阈值，则该 AMR 不得继续执行移动、服务或等待后续任务。

### 6.2 耗电模型

耗电只与路径距离和服务时间有关。

固定参数：

```text
empty_energy_rate = 1.00
loaded_energy_rate = 1.20
service_energy_rate = 0.20
```

空驶耗电：

```text
empty_energy = empty_distance * empty_energy_rate
```

载货耗电：

```text
loaded_energy = loaded_distance * loaded_energy_rate
```

服务耗电：

```text
service_energy = service_time * service_energy_rate
```

等待不耗电。

### 6.3 充电规则

充电点为 `node_type = charger` 的节点。

充电速率固定为：

```text
charge_rate = 10
```

若 AMR 到达充电点时剩余电量为 `b`，充到满电所需时间为：

```text
charge_time = (max_battery - b) / charge_rate
```

充电只允许在充电点进行。

## 7. 路径选择规则

P1 为关键节点之间生成候选路径集合。P1 的任务是提供从一个关键节点到另一个关键节点的可选走法，不负责最终调度决策。

后续调度算法只能从 P1 输出的候选路径中选择，不能临时创造新路径。

对任意一次移动 `a -> b`，若 P1 给出多条候选路径，则调度算法必须从这些候选路径中选择一条作为本次移动路径。路径选择权属于后续调度模块，不由 P1 固定。

路径选择参与以下决策：

```text
1. 降低路径成本；
2. 降低通行时间；
3. 减少转弯次数、避开动态风险区域；
4. 降低与其他 AMR 的二维轨迹冲突风险；
5. 满足动态区域封锁后的可行性要求。
```

各模块对候选路径的使用规则固定为：

```text
P2：在任务分配与排序时选择候选路径，用于计算时间和成本；
P3：在冲突消解时允许重新选择候选路径；
P4：在动态重排时必须根据封锁、延误和新增任务重新评估候选路径。
```

## 8. 二维轨迹冲突规则

本分支不再使用边容量/路口容量口径，冲突按二维轨迹 footprint 判定：P3 将 P1 的轨迹样本（`offset_time, x, y, theta, speed, footprint_radius`）按实际出发时间展开为绝对时空轨迹，若两台 AMR 在相近时刻（时间容差 `TIME_TOLERANCE`）的中心距离小于两者 footprint 半径之和加安全裕量（`SAFETY_MARGIN`），即记录一次轨迹冲突。

该规则在不同层次中的要求不同，见第 11 节。

## 9. 方案评价指标

### 9.1 延期指标

固定使用四类延期指标：

```text
priority_late_count = sum(priority[j] * late[j])
late_count = sum(late[j])
priority_delay = sum(priority[j] * delay[j])
total_delay = sum(delay[j])
```

评价顺序固定为：

```text
先减少高优先级延期任务；
再减少延期任务数量；
再减少高优先级任务延期时长；
最后减少总延期时间。
```

### 9.2 效率指标

系统最大完成时间：

```text
Cmax = max(finish_time[j])
```

### 9.3 路径与负载指标

P1 输出路径字段的量纲固定如下：

```text
distance     路径物理距离，用于距离统计和耗电计算；
travel_time  速度系数为 1.0、空驶状态下的基准通行时间，用于计算实际行驶时间；
total_cost   路径综合成本，抽象成本单位，用于评价路径质量。
```

`total_cost` 不是距离，也不是纯时间。它由 P1 综合通行时间、转角代价和动态区域代价得到（具体构成随 `basic_astar/vg/avg/davg` 算法而异）。

空驶综合成本：

```text
empty_cost = sum(empty_path_total_cost)
```

其中 `empty_path_total_cost` 来自 `path_cost.csv` 的 `total_cost` 字段。

空驶距离：

```text
empty_distance = sum(empty_path_distance)
```

其中 `empty_path_distance` 来自 `path_cost.csv` 的 `distance` 字段。

总路径综合成本：

```text
total_path_cost = sum(empty_path_total_cost + loaded_path_total_cost)
```

总行驶距离：

```text
total_distance = sum(empty_path_distance + loaded_path_distance)
```

行驶时间不直接使用 P1 的 `travel_time` 原值，而是按第 5 节规定结合 AMR `speed` 和载货速度系数计算。

AMR 时间负载：

```text
load[k] = finish_time_of_last_task[k]
```

负载不均衡：

```text
load_balance_penalty = max(load[k]) - min(load[k])
```

## 10. 多目标优化准则

本题采用分层字典序目标与层内加权目标相结合的多目标规划准则。所有方案必须先满足硬约束；在硬约束均满足的前提下，再比较目标函数。
除硬约束、评价指标和分层要求外，具体如何建模、如何求解、如何拆分模块，不作为题目硬性规定，由答题方自行设计。

服务质量层目标：

```text
F1 = (priority_late_count, late_count)
```

时间效率层目标：

```text
F2 = 30.0 * priority_delay
   + 20.0 * total_delay
   + 5.0  * Cmax
```

运行成本层目标：

```text
F3 = 2.0  * empty_cost
   + 10.0 * load_balance_penalty
   + 1.0  * total_energy_used
```

基础层和进阶层均启用耗电计算，`total_energy_used` 按第 6 节计算。基础层不允许通过充电恢复电量；进阶层允许插入充电任务。

静态调度方案的总目标为字典序最小化：

```text
min lex (F1, F2, F3)
```

其比较规则固定为：

```text
1. 先比较 priority_late_count；
2. 若相同，再比较 late_count；
3. 若仍相同，再比较 F2；
4. 若仍相同，再比较 F3。
```

该目标准则的含义是：高优先级任务延期与延期任务数量属于服务承诺，不能被少量路径成本、耗电或负载均衡收益抵消；在服务质量相同的方案中，再用加权和权衡延期时长、完工时间、空驶成本、负载均衡和耗电。

## 11. 分层要求

本题分为两个固定层次。进阶层必须满足基础层的所有规则。

### 11.1 基础层：完整调度闭环，含电量阈值，不含充电

基础层要求系统完成多 AMR 调度主线闭环，包括静态任务调度、冲突处理、动态事件处理和滚动重排。基础层考虑耗电和电量阈值，但不允许插入充电任务。
本层只规定必须达到的结果，不限定采用贪心、规划、插入、局部搜索或其他等价方法。

必须完成：

```text
1. 每个任务必须分配给且仅分配给一台 AMR；
2. 每台 AMR 的任务必须形成线性执行序列；
3. 每个任务的 pickup -> delivery 路径必须存在；
4. 相邻任务之间的 delivery -> pickup 衔接路径必须存在；
5. 每段移动必须从 P1 给出的候选路径中选择一条；
6. 任务不能早于 earliest_start 开始；
7. AMR 实际通行时间必须考虑 speed 和 loaded_speed_factor；
8. 必须生成每个任务的开始时间、完成时间和延期；
9. 必须将路径展开为带时间戳的二维轨迹；
10. 必须按第 8 节检测 AMR 之间的轨迹 footprint 冲突；
11. 必须消除轨迹冲突，且处理后不得存在未解决冲突；
12. 必须处理 area_block、amr_delay、new_task 三类动态事件；
13. 动态事件发生后，必须对未开始任务进行滚动重排；
14. 重排后必须重新检测并处理冲突；
15. 必须按第 6 节计算空驶耗电、载货耗电和服务耗电；
16. 任意时刻 AMR 剩余电量不得低于 battery_safety_threshold；
17. 若 AMR 剩余电量低于阈值，则该 AMR 不得继续执行任务；
18. 基础层不允许插入充电任务。
```

基础层输出：

```text
assignment_result.csv
amr_sequence_summary.csv
schedule_result.csv
trajectory_schedule.csv
conflict_log.csv
reschedule_result.csv
dynamic_event_impact.csv
reschedule_summary.csv
```

基础层验收指标：

```text
missing_loaded_path_count = 0
missing_transition_count = 0
unresolved_trajectory_conflict_count = 0
blocked_area_violation_count = 0
delayed_amr_violation_count = 0
all_dynamic_tasks_scheduled = 1
energy_violation_count = 0
priority_late_count
late_count
priority_delay
total_delay
Cmax
empty_cost
load_balance_penalty
changed_task_count
total_start_shift
F1
F2
F3
```

### 11.2 进阶层：加入充电调度

进阶层在基础层完整调度闭环和电量阈值约束上启用充电任务、充电时间和充电点容量约束。

必须完成：

```text
1. 满足基础层全部要求；
2. 允许在 AMR 任务序列中插入充电任务；
3. 充电任务格式固定为 current_node -> charger -> charge_to_full；
4. AMR 只能充到 max_battery，不允许部分充电；
5. 充电点容量固定为 1，同一时刻同一充电点最多服务一台 AMR；
6. 充电任务必须与普通任务、动态重排和冲突处理共同排程；
7. 动态事件重排后仍必须满足电量、充电点容量和轨迹无冲突约束；
8. 不允许通过任务接力解决电量不足。
```

进阶层新增输出：

```text
charge_schedule.csv
```

进阶层验收指标：

```text
unresolved_trajectory_conflict_count = 0
charger_conflict_count = 0
energy_violation_count = 0
charge_count
total_charge_time
total_waiting_time
F1
F2
F3
```

## 12. 明确不允许的做法

以下做法在本题所有层次中均不允许：

```text
1. 改变 nodes.csv 中的节点位置或节点类型；
2. 改变 floor_zones.csv / floor_obstacles.csv 中的平面布局与障碍物；
3. 临时创造 P1 没有生成的路径；
4. 取消静态任务；
5. 将一个任务拆给多台 AMR 接力完成；
6. 让任务早于 earliest_start 开始；
7. 让 AMR 穿越障碍物或封锁区域；
8. 在进阶层中，让 AMR 在非充电点充电；
9. 在进阶层中，让 AMR 电量低于安全阈值继续执行。
```

## 13. 模块分工

```text
P0：读取固定输入并绘制仓库场景；
P1：生成候选路径和路径成本，不考虑 AMR 分配；
P2：完成任务分配、任务排序、候选路径选择和时间估算；
P3：完成时空占用展开、冲突检测、等待/换路/局部调序消解；
P4：完成动态事件影响识别和滚动重排；
P5：汇总指标，完成基础层与进阶层的对比分析。
```

## 14. 最终题意总结

本题不是单纯最短路问题，而是在固定仓库平面布局和固定任务集合下的多 AMR 调度问题。评价一个方案好坏的标准固定为：先满足所有硬约束，再按分层字典序目标与层内加权目标比较服务质量、时间效率和运行成本。基础层要求实现含电量阈值但不含充电的完整调度闭环；进阶层在完整闭环上加入充电调度。
